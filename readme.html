The engine, end to end

Two parts: a static web app (this site) that predicts matches live in the browser, and a Python pipeline that trains, calibrates, and backtests the model. The app's player data refreshes daily; the pipeline is where you prove the edge.

Run the web app

The app is fully static — no build step. Serve the folder and open it:

  1. Keep index.html, model-math.html, readme.html, styles.css, and players.json in one folder.
  2. On Replit, use a static/HTML Repl and press Run; locally, any static server works (e.g. python -m http.server).
  3. Serving matters: the app fetches players.json, which browsers block over a bare file:// path. Opened as a file it still runs — it just falls back to the built-in seed data.

Daily data updates

The app reads players.json on every load (uncached), so it always shows the latest data. A static page can't refresh itself, though — something has to regenerate that file on a schedule. That's what update_data.py and the included GitHub Action do.

update_data.py pulls recent ATP results from Sackmann's dataset, computes current surface ELO and serve/return rates per player, and rewrites players.json. Run it yourself any time:

python update_data.py            # last 3 seasons
python update_data.py --top 60   # more players
python update_data.py --local atp_matches_2025.csv   # offline test

Today's matches & live odds

update_matches.py pulls upcoming ATP and WTA matches (next 36 hours) with bookmaker odds from The Odds API, runs each one through the same model as the Predictor, and writes matches.json: model win chance, best price and which book has it, EV and a quarter-Kelly stake. The Predictor shows it as Today's matches; Analyse loads a match, its surface, format and odds.

ODDS_API_KEY=your-key python update_matches.py
ODDS_API_KEY=your-key python update_matches.py --hours 48 --regions eu,uk

Surface comes from a built-in table of every ATP tournament: Grand Slams, Masters 1000, 500s, 250s and team events, plus the main WTA-only stops. Stuttgart is grass for ATP and clay for WTA. Indoor events are labelled but the model treats them as ordinary hard courts. A tournament not in the table counts as hard court and shows a “?” on the site. Only men's Grand Slams are best of 5. Players not in players.json — usually qualifiers — are listed under unmatched and skipped.

Automatic daily run (one-time setup)

.github/workflows/update.yml runs every day at 06:20 UTC. It rebuilds players.json and matches.json, commits them, and publishes the site to GitHub Pages. You can also run it by hand from the repo's Actions tab (refresh-data → Run workflow).

  1. Turn on Pages: repo Settings → Pages → Build and deployment → Source: GitHub Actions. The site appears at https://<user>.github.io/<repo>/.
  2. Add the odds key: sign up free at the-odds-api.com (500 requests a month; the daily run uses roughly one per active tournament), then add it under Settings → Secrets and variables → Actions → New repository secret, named ODDS_API_KEY. Without it everything else still updates and the match panel says the feed isn't connected.
  3. Let Actions push: Settings → Actions → General → Workflow permissions → Read and write permissions.

Odds move. The prices are a morning snapshot — check the live price before acting on any "value" flag.

The date stamps on the Predictor show when each file was last rebuilt.

Feed real data to the analysis pipeline

That's the app's data. The separate analysis pipeline (where you backtest and calibrate) ships running on synthetic data. To point it at real matches, grab Jeff Sackmann's ATP files (atp_matches_YYYY.csv) from github.com/JeffSackmann/tennis_atp, then in main.py replace:

df = generate_synthetic_matches()

with:

from data import load_sackmann_csv
df = load_sackmann_csv("atp_matches_2024.csv")  # or concat several years, sorted by date

Two things to fix for real data:

  • Sort chronologically before the walk — ELO must update in match order.
  • The loader sets player A = winner every row, so labels are all True. Shuffle each match's A/B assignment (and flip a_won) so the model trains on balanced outcomes.

Build order, if extending

ELO → logistic baseline → Markov → ensemble → calibrate & verify per-segment → backtest against closing lines with vig → de-vig live odds → fractional Kelly. A calibrated simple model beats an uncalibrated sophisticated one every time.

For real-money use: a real market is sharper than this simulation, edges are thin and decay, and no calibration holds forever — re-fit on a rolling window and treat responsible-gambling limits as core features.
